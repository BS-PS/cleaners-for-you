This data layer models a three-sided cleaning marketplace: **clients** book **cleaners** for a **service** at a specific address, producing a **booking** record linked to a **payment**; completed bookings can generate **reviews** and optionally **complaints**; cleaner income is tracked per booking via **earnings** entries; new cleaner sign-ups flow through **cleanerApplications** with DBS and insurance verification states; the **adminMetrics** object provides aggregated platform-level KPIs and a 12-week revenue series for dashboard charts. All ids are stable string slugs (`cleaner-001`, `booking-001`, etc.) so any screen can reference fixtures deterministically, and all dates are generated relative to `new Date()` at module load time so the demo data never goes stale.
